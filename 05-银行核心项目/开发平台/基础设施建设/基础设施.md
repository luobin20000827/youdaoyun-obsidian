# 基础设施

- Nexus_Maven仓库
  - Tips
    - 1.开放Anonymous Access，然后只把group放给开发者，就能让其只能拉取组件但不能上传到组件仓库
    - 2.常熟这边一些dev，xyd命名的仓库多是以前的一些老仓库，新设计的仓库都是以csrcb命名的
    - 3.从group拉取时，是从上至下从repo中寻找符合条件的包，所以自由的组件要放在上面，公开的放下面
    - 4.路径记录溯源：对于下级法人行增量的一些组件，就需要放到省联社法人行组件专属仓库中做统一管理（统一扎口）
  - 架构设计
    - 全行级
      - 省联社开发时自有的涉及的组件
    - 公司方
      - 大的外包公司可以建仓库单独管理组件
        - jsrcb-company-xxx
      - 小公司或者组件量较少的时候就丢到company统一管理
        - jsrcb-company
      - 法人行视同公司方仓库管理
    - 代理仓库
      - 公网代理仓库
      - 公司方代理仓库（区别于上文公司方：驻场使用本地仓库/远程仓库）
        - jsrcb-company-proxy-xxx
      - 法人行
        - 可以将下级法人行自有组件group的maven仓库（若有）作为代理（处理存量）
    - 组
      - 公司组
        - 是否需要分公司隔离，每一个公司拿到全行级+该公司的代理/本地仓库+公网代理组
      - 代理组
        - 公网代理仓库组
  - 仓库类型
    - 本地hosted
    - 代理proxy
    - 组group：仓库的集合
  - 服务器需求：需要存储空间2T以上
  - 权限设置
    - 新设一个公司仓库管理员，对公司仓库内容有增删改查的权限
    - 常熟这边的做法是组件的上传都统一从admin/公司管理员处上传
    - 代码扫描or漏洞管理
    - 其他按照默认配置
  - 仓库语言
    - maven
    - npm
    - docker
    - go
    - python
  - 初步建仓规划
    - maven_jsrcb_hosted
    - maven_jsrcb_company_hosted
    - maven_jsrcb_xxx法人行_hosted
    - maven_internet__xxx_proxy
    - group
      - maven_internet_proxy_group
      - maven_jsrcb_group
      - maven_jsrcb_company_group
  - 迁移
    - 复制整个sonatypework
    - 更改/bin/vmoptions
  - 实际建仓
    - maven/npm_open_proxy是拉的常熟的公网代理
    - maven_jsrcb_help_hosted是2024.8.7本地上传的常熟这边后端依赖（基本上），考虑到后续可能要改名就先不取jsrcb_hosted
