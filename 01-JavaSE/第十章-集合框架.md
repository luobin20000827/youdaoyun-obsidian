# 第十章-集合框架

## 10.1 集合框架的概述

*   最常见的容器：数组List
    *   初始化长度不可变
    *   有序依次紧密排列，且可重复
    *   现成的方法和属性不多
    *   增删插入性能比较差
*   java集合框架体系（java.util包下）
    *   java.util.Collection:存储一个一个数据
        *   子接口List-存储有序可重复的数据：ArrayList（主要实现类），LinkedList，Vector
        *   子接口Set-无序不可重复的数据：HashSet（主要实现类）、LinkedHashSet等

    *   java.util.Map:存储一对一对的数据

## 10.3 Iterator(迭代器)接口

### 10.3.1 迭代器用法

*   java.lang.iterator也是集合中的医院，但不用于存储数据，而是用于遍历iterator中的元素
*   Collection接口继承了java.lang.Iterable接口，该接口有一个iterator()方法，那么所有实现了Collection接口的集合类都有一个iterator()方法，用以返回一个实现了Iterator接口的对象。
    *   public Iterator iterator(): 获取集合对应的迭代器，用来遍历集合中的元素的。
    *   集合对象每次调用iterator()方法都得到一个全新的迭代器对象，默认游标都在集合的第一个元素之前。
*   接口的常用方法如下：
    *   public E next():返回迭代的下一个元素。//这里的E指的是泛型，在这里的作用类似一个占位符
    *   public boolean hasNext():如果仍有元素可以迭代，则返回 true。
    *   注意：在使用next()时必须调用hasNext()进行检测，否则会抛出NoSuchElementException

### 10.3.2 迭代器的执行原理

*   内部用指针来跟踪集合中的元素，而调用next()时就会返回当前位置的值，并将索引值加1
    ![image](https://github.com/luobin7/-java-/raw/main/%E7%AC%AC12%E7%AB%A0_%E9%9B%86%E5%90%88%E6%A1%86%E6%9E%B6/images/image-20220407235130988.png)
*   此外，迭代器还包含了删除元素的remove()方法，此方法会删除上一次next()返回的元素
    *   注意，如果尚未next()或是上次next()回的结果已被remove，则再调用remove()会报错IllegalException
    *   在迭代器中remove(）结果会影响到集合
    *   此外，此remove为iterator的remove，区别于集合Collection子接口类自带的remove方法
    *   对比自带的remove()，迭代器的remove()更方便在迭代过程中进行逻辑判断,再根据结果进行删除（在JDK 8.0中，Collection接口也引入了类似方法removeIf()）

### 10.3.3 foreach循环

*   JDK5.0中推出，专门用来遍历数组和集合
*   语法格式：

## 10.4 Collection子接口1：List

### 10.4.1 List特性

*   一般用`java.util.List`来代替数组（ArrayList,LinkedList都是它的一个实现接口）
*   List是有序的、可重复的、顺序索引的

### 10.4.2 List接口方法

*   List除了继承了Collection集合中的一些方法外，还添加了一些根据索引对集合中元素进行操作的方法
*   插入元素
    *   `void add(int index, Object ele)` 集合位置插入
    *   `boolean addAll(int index, Collection eles)`从index位置将eles中元素都添加进来
*   获取元素
    \-` Object get(int index)`:获取index位置的元素
    *   `List subList(int formIndex, int toIndex)`:获取指定范围内的一子集和
*   获取索引
    *   `int indexOf(Object obj)`:返回obj在集合中首次出现的位置
    *   `int lastIndexOf(Object obj)`:返回obj在当前集合中末次出现的位置
*   删除与替换元素
    *   `Object remove(int index)`:移除指定index位置的元素，并返回此元素
    *   `Object set(int index, Object ele)`:设置指定index位置的元素为ele

### 10.4.3 List接口主要实现类 ：ArrayList

*   ArrayList是一个变长的数组：与vector主要的区别就在于线程安全和增长策略
*   注意：Arrays.asList(…) 方法返回是一个固定长度的 List 集合

### 10.4.4 List的实现类之二：LinkedList

*   频繁进行插入删除操作的数组，建议使用链表类数组LinkedList。
*   特有方法：
    *   void addFirst(Object obj)
    *   void addLast(Object obj)
    *   Object getFirst()
    *   Object getLast()
    *   Object removeFirst()
    *   Object removeLast()

### 10.4.5 List的实现类之三：Vector

*   三种实现接口中，Vector速度是最慢的，因此应尽量避免使用
*   特有方法：
    *   void addElement(Object obj)
    *   void insertElementAt(Object obj,int index)
    *   void setElementAt(Object obj,int index)
    *   void removeElement(Object obj)
    *   void removeAllElements()

## 10.5 Collection子接口2：Set

### 10.5.1 Set接口概述

*   Set接口是Collection的子接口，Set接口相较于Collection接口没有提供额外的方法
*   与List子接口最大的不同就是Set是无序的（有一些实现是有顺序的）且不允许重复的（可以用来过滤重复）
*   Set集合支持的遍历方式和Collection集合一样：foreach和Iterator。
*   Set的常用实现类有：HashSet、TreeSet、LinkedHashSet。
*   底层都是基于Map实现的

### 10.5.2 Set的主要实现类：HashSet

#### 10.5.2.1 概述

*   HashSet是Set接口的主要实现类，大多数时候使用Set集合都是用这个实现类
*   HashSet使用Hash算法来存储集合中的元素，性能较好
*   HashSet具有以下特点：
    *   不能保证元素排列顺序
    *   不是线程安全的
    *   集合元素可以是null
*   HashSet中判断两个元素相等的标准：两个对象的hashCode()得到的哈希值一致，且两个对象的equals方法返回值为true
*   ==对于存放在Set容器中的对象，对应的类一定要重写hashCode()和equals(Object obj)方法，以实现对象相等规则。即：“相等的对象必须具有相等的散列码”。==
*   HashSet集合中元素的无序性，不等同于随机性。这里的无序性与元素的添加位置有关。具体来说：我们在添加每一个元素到数组中时，具体的存储位置是由元素的hashCode()调用后返回的hash值决定的。导致在数组中每个元素不是依次紧密存放的，表现出一定的无序性。（考虑到有哈希碰撞，即便元素值没有改变，在遇到哈希碰撞时他们的位置也会变化）

#### 10.5.2.2 HashSet中添加元素的过程

*   第1步：存入-hashcode()方法调用-散列函数决定存储位置
*   第2步：对应位置上没有元素则添加成功；若有，则对比是否相等（hashcode
    () --> equals()），若最后还是相等，则添加失败
*   第3步，若是hashcode()/equals()对比的结果不等，则会通过链表的方式继续存储

```
//一道有助于理解HashSet存储过程的面试题
HashSet set = new HashSet();
Person p1 = new Person(1001,"AA");
Person p2 = new Person(1002,"BB");

set.add(p1);
set.add(p2);
p1.name = "CC";//在这里p1的hashCode()值改变了，但他的存储位置并不会变
set.remove(p1);//remove的时候因为p1的hashCode值改变而找不到要remove的元素，remove失败
System.out.println(set);

set.add(new Person(1001,"CC"));
System.out.println(set);
// 再创建(1001,“CC”)这个对象并计算它的哈希值c，故结果有3个：[person={1001,"CC"},person={1002,"BB"},person={1001,"CC"]
set.add(new Person(1001,"AA"));
System.out.println(set);

//其中Person类中重写了hashCode()和equal()方法//和最开始的对象相同，哈希值相同。比较equals()，属性不同。故能添加aa对象，输出4个对象 [person={1001,"CC"},person={1002,"BB"},person={1001,"CC"，person={1001,"AA"]

```

#### 10.5.2.3 重写hashCode()方法的基本原则

*   在程序运行时，同一个对象多次调用 hashCode() 方法应该返回相同的值。
*   当两个对象的 equals() 方法比较返回 true 时，这两个对象的 hashCode() 方法的返回值也应相等。
*   对象中用作 equals()方法比较的 Field，都应该用来计算hashCode值。

#### 10.5.2.4 重写equals()方法的基本原则

*   重写equals方法的时候一般都需要同时复写hashCode方法。通常参与计算hashCode的对象的属性也应该参与到equals()中进行计算。
*   推荐：开发中直接调用Eclipse/IDEA里的快捷键自动重写equals()和hashCode()方法即可。

<!---->

    //自带hashCode()方法在Jdk7.0中引入的Objects类中实现
    public static int hashCode(Object[] a) {
        if (a == null)
            return 0;

        int result = 1;

        for (Object element : a)
            result = 31 * result + (element == null ? 0 : element.hashCode());

        return result;
    }

*   为什么用Eclipse/IDEA复写hashCode方法，有31这个数字？

<!---->

    首先，选择系数的时候要选择尽量大的系数。因为如果计算出来的hash地址越大，所谓的“冲突”就越少，查找起来效率也会提高。（减少冲突）

    其次，31只占用5bits,相乘造成数据溢出的概率较小。

    再次，31可以 由i*31== (i<<5)-1来表示,现在很多虚拟机里面都有做相关优化。（提高算法效率）

    最后，31是一个素数，素数作用就是如果我用一个数字来乘以这个素数，那么最终出来的结果只能被素数本身和被乘数还有1来整除！(减少冲突)

### 10.5.3 Set实现类之二：LinkedHashSet

*   LinkedHashSet 是 HashSet 的子类，不允许集合元素重复。
*   LinkedHashSet 根据元素的 hashCode 值来决定元素的存储位置，但它同时使用双向链表维护元素的次序，这使得元素看起来是以添加顺序保存的。
*   LinkedHashSet插入性能略低于 HashSet，但在迭代访问性能好。

### 10.5.4 Set实现类之三：TreeSet

#### 10.5.4.1 TreeSet概述

*   TreeSet 是 SortedSet 接口的实现类，TreeSet最大的特性在于 可以按照添加的元素的指定的属性的大小顺序进行遍历。
*   它的底层使用红黑树来存储数据
*   与前面的Collection实现的Comparable-compareTo(obj)与Comparator-compare(o1,o2)（构造时当参数传入TreeSet）一样，TreeSet里面也可以实现自然排序和定制排序
    *   因为只有相同类的两个实例才会比较大小，所以向 TreeSet 中添加的应该是同一个类的对象。
    *   对于 TreeSet 集合而言，它判断两个对象是否相等的唯一标准是：两个对象通过 compareTo(Object obj) 或compare(Object o1,Object o2)方法比较返回值。返回值为0，则认为两个对象相等。(有别于HashSet考虑hashCode())

## 10.6 Map接口

### 10.6.1 概述

*   Map与Collection最大的不同就在于它存储的不是孤立的元素，而是映射关系（键值对）（单列集合-双列集合）
*   Map 中的 key 和 value 都可以是任何引用类型的数据。但常用String类作为Map的key。
*   Map接口的常用实现类（HashMap是 Map接口使用频率最高的实现类）：
    *   HashMap：主要实现类，线程不安全，效率高，可以添加null（kv），使用数组+单向链表+红黑树存储
        *   LinkedHashMap：双向链表，适合遍历
    *   TreeMap：红黑树
    *   Hashtable：古老实现类；线程安全；效率比较低，不支持null
        *   Properties：Key和Value都是String，用来处理属性文件
*   ![image](https://github.com/luobin7/-java-/raw/main/%E7%AC%AC12%E7%AB%A0_%E9%9B%86%E5%90%88%E6%A1%86%E6%9E%B6/images/image-20220409001015034.png)。

### 10.6.2 Key-value特点

![image](https://github.com/luobin7/-java-/raw/main/%E7%AC%AC12%E7%AB%A0_%E9%9B%86%E5%90%88%E6%A1%86%E6%9E%B6/images/image-20220409001213720.png)

*   Map中的key用Set（这里指的是Set的特性，实际上Java里的Set是基于HashMap实现的）来存放，不允许重复，因此Map对象所对应的类也必须重写hashCode()和equals()方法
*   而Map中的value是可重复的，无序的
*   每一个kv对都组成了一个entry，而由于key是无重复的，因此，每个entry也构成了set

### 10.6.3 常用方法

*   增
    *   void put(Object key,Object value)
    *   void putAll(Map m)
*   删
    *   Object remove(Object key) 删除对应key的kv对且返回对应的value
    *   void clear()
*   改
    *   void put(Object key,Object value) HaspMap中通过“增”来实现“改”：当你尝试添加一个已经存在的键时，如果新的值和旧的值不同，则旧的值会被新的值替换，这就达到了更改的目的。
*   查
    *   Object get(Object key)：获取指定key对应的value
*   长度
    *   int size()
*   遍历
    *   遍历key：Set keySet()
    *   遍历Value：Collection values()
    *   遍历entry：Set entrySet() // key==value的形式

### 10.6.4 Map的主要实现类：HashMap

*   具体见在概述中

### 10.6.5 Map实现类之二：LinkedHashMap

*   是HashMap的子类，在HashMap基础上增加了一对双向列表来记录添加元素的先后顺序。
*   遍历的顺序默认是元素的插入顺序（构造器中提供了一个访问数据因子accessorder，若为true则最频繁访问的元素就会被放到链表的末尾，而最少访问的元素会被放在链表的开头。）
*   通过哈希表结构可以保证键的唯一、不重复，需要键所在类重写hashCode()方法、equals()方法。

### 10.6.6 Map实现类之三：TreeMap

*   TreeMap存储 key-value 对时，需要根据 key-value 对进行排序。TreeMap 可以保证所有的 key-value 对处于有序状态。
*   TreeSet底层使用红黑树结构存储数据
    TreeMap 的 Key 的排序：
    自然排序：TreeMap 的所有的 Key 必须实现 Comparable 接口，而且所有的 Key 应该是同一个类的对象，否则将会抛出 ClasssCastException
    定制排序：创建 TreeMap 时，构造器传入一个 Comparator 对象，该对象负责对 TreeMap 中的所有 key 进行排序。此时不需要 Map 的 Key 实现 Comparable 接口
*   TreeMap判断两个key相等的标准：两个key通过compareTo()方法或者compare()方法返回0。

### 10.6.7 Map实现类之四：Hashtable

*   Hashtable在JDK1.0中就定义了，它是线程安全的
*   Hashtable的子类Properties（配置文件）依然活跃在历史舞台，它是一个唯一和IO流相结合的集合

### 10.6.8 Map实现类之五：Properties

*   用来与属性文件处理
*   Properties 中要求 key 和 value 都是字符串类型
*   建议使用setProperty(String key,String value)方法和getProperty(String key)方法

## 10.7 Collections工具类

*   区别于List和Set的父接口Collection，Collections 是一个操作 Set、List 和 Map 等集合的工具类。

### 10.7.1 常用方法
- 它提供了一系列静态的方法对集合进行增删改查控制

#### 10.7.1.1 排序
- reverse(List)：反转 List 中元素的顺序
- shuffle(List)：对 List 集合元素进行随机排序
- sort(List)：根据元素的自然顺序对指定 List 集合元素按升序排序（前提是同一类型的数据）
- sort(List，Comparator)：根据指定的 Comparator 产生的顺序对 List 集合元素进行排序
- swap(List，int， int)：将指定 list 集合中的 i 处元素和 j 处元素进行交换

#### 10.7.1.2 查找
- Object max(Collection)：根据元素的自然顺序，返回给定集合中的最大元素
- Object max(Collection，Comparator)：根据 Comparator 指定的顺序，返回给定集合中的最大元素
- Object min(Collection)：根据元素的自然顺序，返回给定集合中的最小元素
- Object min(Collection，Comparator)：根据 Comparator 指定的顺序，返回给定集合中的最小元素
- int binarySearch(List list,T key)在List集合中查找某个元素的下标，但是List的元素必须是T或T的子类对象，而且必须是可比较大小的，即支持自然排序的。而且集合也事先必须是有序的，否则结果不确定。
- int binarySearch(List list,T key,Comparator c)在List集合中查找某个元素的下标，但是List的元素必须是T或T的子类对象，而且集合也事先必须是按照c比较器规则进行排序过的，否则结果不确定。
- int frequency(Collection c，Object o)：返回指定集合中指定元素的出现次数

#### 10.7.1.3 复制替换
-void copy(List dest,List src)：将src中的内容复制到dest中
- boolean replaceAll(List list，Object oldVal，Object newVal)：使用新值替换 List 对象的所有旧值
- 提供了多个unmodifiableXxx()方法，该方法返回指定 Xxx的不可修改的视图。

#### 10.7.1.4 添加
- boolean addAll(Collection c,T... elements)将所有指定元素添加到指定 collection 中。
