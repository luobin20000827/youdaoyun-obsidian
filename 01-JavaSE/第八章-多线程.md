## 1.基本概念

*   程序 program：静态的对象，不执行时就是磁盘上的一堆文件
*   进程 process：程序加载到内存中开始运行时便成为一个进程
*   线程 thread：cpu调度与执行的最小单位，拥有自己的独立执行路径和程序计数器，但可以访问同一个进程中的共享数据。
*   对于线程而言，蓝色区域为每一个线程独享的，而黄色区域时一个进程内所有线程共享的
*   ![image](https://github.com/luobin7/-java-/raw/main/%E7%AC%AC10%E7%AB%A0_%E5%A4%9A%E7%BA%BF%E7%A8%8B/images/image-20220514175737426.png)
*   抢占式调度or分时调度（Java使用抢占式）
*   并发（concurrency）与并行（parallel）概念
    *   并行指的是多个指令在多个cpu上同时执行。
    *   并发指多条指令在单个CPU上快速轮换，本质上是分时的交替运行。

## 2.创建与启动线程

### 2.1 概述

*   Jvm允许多线程运行程序，使用`java.lang.Thread`类表示线程，所有线程对象都必须是`Thread`类或者其子类的对象。
*   每个线程都是通过特定`Thread`对象的`run(`)方法来完成操作的，因此`run()`方法也被称为线程执行体
*   启动使用`start()`,先启动再运行`run()`

### 2.2 继承Thread类

Java中通过构建Thread子类来启动多线程的步骤如下：

*   定义`Thread`子类，重写其`run`方法，该`run()`方法的方法体就代表了线程应该完成的任务
*   创建该子类对象
*   调用对象的`start()`方法来启动该线程，且一个线程对象只能使用一次`start()`方法启动，如果重复启动了就会抛出异常
*   此时的run()方法是由JVM自动调用的，如果只是手动调用run()方法，则就只是普通方法，没有启动多线程模式

<!---->

    package com.atguigu.thread;
    //自定义线程类
    public class MyThread extends Thread {
        //定义指定线程名称的构造方法
        public MyThread(String name) {
            //调用父类的String参数的构造方法，指定线程的名称
            super(name);
        }
        /**
         * 重写run方法，完成该线程执行的逻辑
         */
        @Override
        public void run() {
            for (int i = 0; i < 10; i++) {
                System.out.println(getName()+"：正在执行！"+i);
            }
        }
    }

            //创建自定义线程对象2
            MyThread mt2 = new MyThread("子线程2");

### 2.3 Thread的接口写法

*   因为Java中有单继承的限制，因此多线程还能用`Runnable`接口实现，来使该接口的实现类具有多线程类的特征，其步骤如下：
    *   定义`Runnable`接口的实现类，并重写接口的`run()`方法，此`run`方法的方法体同样是该线程的线程方法体
    *   创建该实现类的实体，并用此实例作为`Thread`类的`target`参数来创建`thread`对象
    *   调用线程的`start()`方法，启动线程，调用`Runnable`接口实现类的`run()`方法。
    *   和继承写法一样，接口写法中的多线程依然是依赖thread对象的start()--->run()这一过程来实现的，构建runnable对象和run()方法仅作为线程执行体。

<!---->

    public class ThreadRunnableClass implements Runnable {
        private int i;

        public ThreadRunnableClass(int i) {
            this.i = i;
        }
        @Override
        public void run() {
            long result = 1L;
            for(int j =2;j<=i;j++) {
                result *= j;
                System.out.println(result);
            }
        }
    }

<!---->

    public class Test {
        public static void main(String[] args) {

            ThreadRunnableClass m1 = new ThreadRunnableClass(10);
            Thread t1 = new Thread(m1,"子线程1");
            t1.start();
            ThreadRunnableClass m2 = new ThreadRunnableClass(10);
            Thread t2 = new Thread(m2,"子线程2");
            t2.start();
        }

    }

### 2.4 变形写法

*   使用匿名内部类对象来实现线程创建于启动

<!---->

    new Thread("新的线程！"){
    	@Override
    	public void run() {
    		你的方法
    	}
    }.start();

<!---->

    new Thread(new Runnable(){
    	@Override
    	public void run() {
    		你的方法
    		}
    	}
    }).start();
- 一般来说用后者也就是`runnable`接口来实现匿名线程对象的更多，这么做更符合`Thread`与任务代码的解耦要求，也符合`Composition over inheritance`的设计原则


## 3.Thread类的常用结构

### 3.1 构造器

*   public Thread()：分配一个新的线程对象
*   public Thread(String name)：分配一个指定名字的新对象
*   public Thread(Runnable target)：指定创建线程的目标对象，这个对象实现了runnable接口中的run方法
*   public Thread(Runnable target，String name)在上面的基础上给线程加上了名字

### 3.2 常用方法

*   public void run() :此线程要执行的任务在此处定义代码。
*   public void start() :导致此线程开始执行; Java虚拟机调用此线程的run方法。
*   public String getName() :获取当前线程名称。
*   public void setName(String name)：设置该线程名称。
*   public static Thread currentThread() :静态方法，返回对当前正在执行的线程对象的引用。`Thread.currentThread()`通常用于主线程和Runnable实现类；
*   public static void sleep(long millis) :使当前正在执行的线程以指定的毫秒数暂停（暂时停止执行）。
*   public static void yield()：yield只是让当前线程暂停一下，让系统的线程调度器重新调度一次，希望优先级与当前线程相同或更高的其他线程能够获得执行机会，但是这个不能保证，完全有可能的情况是，当某个线程调用了yield方法暂停之后，线程调度器又将其调度出来重新执行。==要注意的是，使用诸如sleep(),join()等涉及堵塞操作的方法时，需使用try-catch或throws等异常捕获结构来处理可能出现的interrupt错误。==
* public final boolean isAlive()：测试线程是否处于活动状态。如果线程已经启动且尚未终止，则为活动状态。
* void join() ：等待该线程终止。==例如在main方法中使用t1.join()就是要让join线程执行完才让主程序继续进行。==
- void join(long millis) ：等待该线程终止的时间最长为 millis 毫秒。如果millis时间到，将不再等待。
- void join(long millis, int nanos) ：等待该线程终止的时间最长为 millis 毫秒 + nanos 纳秒。
- 一些优先级相关的方法
- Thread类的三个优先级常量：
    MAX_PRIORITY（10）：最高优先级
    MIN _PRIORITY （1）：最低优先级
    NORM_PRIORITY （5）：普通优先级，默认情况下main线程具有普通优先级。
- public final int getPriority() ：返回线程优先级
- public final void setPriority(int newPriority) ：改变线程的优先级，范围在[1,10]之间。

## 5.线程安全问题
### 5.1. 同步机制解决安全问题（Synchronized）
1. 同步代码块：synchronized关键字加在区块面前，表示对区块的资源实现互斥访问：

```
synchronized(同步监视器/锁){
    //需要被同步的代码
    //同步监视器是用来对齐当前进入代码块的线程的，可以理解为一把锁
    //因此此处的同步监视器必须是一个唯一的变量，在runnable接口实现多线程的情况中，同步监视器可以考虑用this，也可以new一个obj充当，在继承实现Thread的方式中，可以考虑实现当前类.class
}
```
2. 同步方法：synchronized 关键字直接修饰方法,应该直接跟在访问修饰符之后，表示同一时刻只有一个线程能进入这个方法，其他线程在外面等着：

```
public synchronized void method(){
 //可能会产生线程安全问题的代码
}
```

### 5.2 懒汉式中的线程安全
- 饿汉式在类初始化时单例对象，不存在线程安全问题
- 懒汉式只有在getinstance()时才创建对象，因此有可能出现线程安全问题
- 解决方式：双重检查锁定(Double-Check Locking)

```
package com.atguigu.single.lazy;

public class LazyOne {
    private static LazyOne instance;

    private LazyOne(){}

    //方式1：
    public static synchronized LazyOne getInstance1(){
        if(instance == null){
            instance = new LazyOne();
        }
        return instance;
    }
    // 这种写法会让每次有线程获取实例时，其他线程都会进入等待
    
    //方式2：
    public static LazyOne getInstance2(){
        synchronized(LazyOne.class) {
            if (instance == null) {
                instance = new LazyOne();
            }
            return instance;
        }
    }
    //方式3：双重检查锁定 ：第一重检查：不为空，直接返回，避免实例已经创建时额外的同步开销
    第二重检查：没有线程在进行判断时已经创建了实例
    public static volatile LazyOne getInstance3(){
        if(instance == null){
            synchronized (LazyOne.class) {
                try {
                    Thread.sleep(10);//加这个代码，暴露问题
                } catch (InterruptedException e) {
                    e.printStackTrace();
                }
                if(instance == null){
                    instance = new LazyOne();
                }
            }
        }

        return instance;
    }
    /*
    注意：上述方式3中，有指令重排问题
    mem = allocate(); 为单例对象分配内存空间
    instance = mem;   instance引用现在非空，但还未初始化
    ctorSingleton(instance); 为单例对象通过instance调用构造器
    从JDK2开始，分配空间、初始化、调用构造器会在线程的工作存储区一次性完成，然后复制到主存储区。但是需要   
    volatile关键字，避免指令重排。
    */
    
}

```

### 5.3 死锁

- 不同的线程互相占住彼此所需的资源不释放
- 诱发的原因：
    - 互斥：同步的本质要求
    - 占用且等待：一开始就获取全部资源
    - 不可抢夺：允许回退
    - 循环等待：线性资源优先级

### 5.4 Lock锁
- 在jdk5中，Java引入了lock新特性
- java.util.concurrent.locks.Lock接口是控制多个线程对共享资源进行访问的工具。锁提供了对共享资源的独占访问，每次只能有一个线程对Lock对象加锁，线程开始访问共享资源之前应先获得Lock对象。
- 创建对象-执行lock()方法，锁定共享资源的调用-unlock()方法，释放锁定。

## 6.线程间通信

### 6.1 为什么线程间需要通信
- 任务协作
- 依赖等待唤醒机制

### 6.2 等待唤醒机制              
- wait()等待 ----  notify()唤醒 --- notifyAll()
- 三个方法必须在同步代码块或是同步方法中使用，且其调用者必须是该部分的同步监视器（这里可以new一个obj，比较方便）
- notify唤醒的是被wait()的线程中优先级最高的线程，且续上被wait()时的状态继续运行
- 
```
public class CommunicationTest {
    public static void main(String[] args) {
        Number number = new Number();
        Thread t1 = new Thread(number);
        Thread t2 = new Thread(number);

        t1.setName("线程1");
        t2.setName("线程2");

        t1.start();
        t2.start();
    }
}

class Number implements Runnable {
    private int number = 1;
//    private Object obj = new Object();

    @Override
    public void run() {
        while(true){
            synchronized (this){
                this.notify();
                if(number<=100){
                    System.out.println(Thread.currentThread().getName() + ":"+ number++);
                    try{
                        this.wait();
                    }catch (InterruptedException e){
                        e.printStackTrace();
                    }
                }else break;
            }
        }

    }
}
```

- sleep()和wait()的区别
    - 位置：一个是类方法，一个是Thread静态方法
    - 场景：一个限制在同步方法内使用
    - 是否释放同步监视器（锁）
