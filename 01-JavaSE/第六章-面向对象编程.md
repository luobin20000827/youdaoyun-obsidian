# 1.类和对象的基本概述
## 1.1 什么是类和对象
- 类（Class）和对象（Object）都是面向对象的核心概念
- 前者表述的是堆一类具有相同事物的抽象表述（可以理解为蓝图），后者则是指该类事物的具体个体，又被称为实例（instance）（按照蓝图生产出的一个个商品）
- 从面向过程编程OOP(Procedure Oriented Programming)到面向对象编程OAP(Object Oriented Programming)：从基于过程中的一个个函数方法来解决问题到依赖对象与类来解决问题。

## 1.2 类的成员概述

- 类是一组相关**属性**和**方法**的集合
    - 属性：类的状态信息，对应类中的成员变量（类（飞机）内的 （制造商、型号、发动机等等）属性）
        - 成员变量 <=> 属性 <=> Field
        


    - 行为：对应类中的成员方法，该类事务能做什么，有什么操作
        - (成员)方法 <=> 函数 <=> Method

## 1.3 类的定义


```
[修饰符] class 类名{
    属性声明;
    方法类型;
}
```

# 2.类的成员之一：成员变量
## 2.1 如何声明成员变量
- 语法格式

```
[修饰符1] class 类名{
[修饰符2] 数据类型 成员变量名 [= 初始化值];
}

```

```
public class Person{
private int age; //声明private变量 age
public String name = “Lila”; //声明public变量 name
}
```

- 成员变量是指在类内，但是在方法外的变量（方法内称为局部变量）
- 常见的修饰符包括 `private,protected,public`,缺省等等
- 成员变量可以是任何数据类型，无论是基本数据类型还是引用数据类型
- 成员变量可以初始化值，若无初始化值便使用默认值

## 2.2 成员变量和局部变量的不同之处
![image](https://github.com/luobin7/-java-/blob/main/%E7%AC%AC06%E7%AB%A0_%E9%9D%A2%E5%90%91%E5%AF%B9%E8%B1%A1%E7%BC%96%E7%A8%8B%EF%BC%88%E5%9F%BA%E7%A1%80%EF%BC%89/images/%E5%B1%8F%E5%B9%95%E6%88%AA%E5%9B%BE%202024-02-07%20171300.png?raw=true)
 - **作用域**：每个属性都有对应的作用域；封装在类内方法外的称为成员变量；封装在方法里的变量就称为局部变量
 - **内存位置**：随着对象的创建，属性（成员变量）也会随之存储在堆空间（凡是new出来的结构都存放在堆空间）中，而局部变量存放在栈空间中
- **生命周期**：属性随着对象的创建而创建，随着对象的结束而结束;而局部变量的生命周期与方法相连（随着方法出栈而消亡）。
- **修饰符**：属性可以使用权限修饰符(`public,protetced,private`，省略等等)修饰；而局部变量不能使用任何权限修饰符进行修饰
- **默认值**：属性都是有默认初始化值的（若没有显式初始化，属性就会有一个默认的初始化值（0，null））；而局部变量都没有默认初始化值，即在使用局部变量（调用方法）时必须要有显式的赋值

# 3.类的成员之二：方法
## 3.1 方法（类内的函数）的定义
- 方法是对类功能的抽象，以此实现代码复用，减少冗余并简化代码
- Java中的方法必须写在类中，不能独立声明
- 方法可以调用类中的其他方法，但不可以在方法内部再定义方法
- 方法是先声明后使用，不调用不执行（声明的顺序不影响main方法中的顺序执行）

## 3.2 方法的声明

- **语法格式**：

    - 其中[修饰符] 返回值类型 方法名([形参列表])[throws 异常列表]被称为**方法头**，也叫**方法签名**
    - 方法的功能代码也被叫做方法体，这部分对调用者而言往往时隐藏的
    - 一个完整的方法 = 方法头 + 方法尾

```
[修饰符] 返回值类型 方法名([形参列表])[throws 异常列表]{
方法体的功能代码
}
```



- **修饰符**：同类的修饰符，例如：`public、protected、private、static、abstract、native、final、synchronized`等
    - 其中，权限修饰符有`public、protected、private`。在讲封装性之前，我们先默认使用`pulbic`修饰方法
    - 其中，根据是否有`static`，可以将方法分为静态方法和非静态方法。其中静态方法又称为类方法（所有实例公用一份），非静态方法又称为实例方法。咱们在讲`static`前先学习实例方法。
- **返回值类型**  
    - 我们之前常见到的`void`，指的是**无返回值**类型
    - 有返回值则搭配方法中的`return`使用
    - `return`会结束本次方法

- **方法名**：做到见名知意
- **形参列表**：如果有参数，每一个参数都要指定数据类型和参数名，多个参数之间使用逗号分隔
    - 一个参数： (数据类型 参数名)
    - 二个参数： (数据类型1 参数1, 数据类型2 参数2)
### 3.3 调用方法的内存分析
- 方法在声明后但没有调用时，就已经在方法区中加载存储（.class字节码文件）
- 当方法被调用时，方法就会以栈帧的形式进入到栈内存中运行
- 同时可能会在堆内存中，添加新的对象数据。当这个方法执行结束，方法对应的栈帧会被弹出（即清理掉）

## 3.4 方法的重载 Overload
- **定义**：在同一个类中，允许存在一个以上的同名方法，只要它们的参数列表不同即可
    - 同一个类内
    - 参数列表不同：参数个数或参数类型不同
    - 重载与修饰符、返回值类型无关，只看参数列表，且参数列表必须不同。调用时，根据方法参数列表的不同来区别
- **重构方法的调用**
    - 具体调用哪个方法，jvm会从参数列表的角度进行匹配，找个数、类型最匹配的
    - 如果多个方法可以匹配的话，jvm会报错

## 3.5 可变个数的形参
- 在JDK 5.0 中提供了Varargs(variable number of arguments)机制。即当定义一个方法时，形参的类型可以 确定，但是形参的个数不确定，那么可以考虑使用可变个数的形参

```
方法名(参数的类型名 ...参数名)
```


```
//JDK 5.0以前：采用数组形参来定义方法，传入多个同一类型变量
public static void test(int a ,String[] books);
//JDK5.0：采用可变个数形参来定义方法，传入多个同一类型变量
public static void test(int a ,String...books);
```
- 本质就是减去了数组的声明过程，方法会将输入的参数视作列表计算
- 可变个数的形参必须放在声明参数中的最后一个，且只能有一个

## 3.6 方法的参数传递机制

### 3.6.1 形参与实参

- 形参（formal parameter）：在定义方法时，方法名后面括号()中声明的变量称为形式参数，简称形参。
- 实参（actual parameter）：在调用方法时，方法名后面括号()中的使用的值/变量/表达式称为实际参数，简称实参。

### 3.6.2 值传递

- Java里方法的参数传递方式只有一种： 值传递 。 即将实际参数值的副本（复制品）传入方法内，而参数本身不受影响。
    - 形参是**基本数据类型**：将实参基本数据类型变量的“**数据值**”传递给形参
    - 形参是**引用数据类型**：将实参引用数据类型变量的“**地址值**”传递给形参
        - 也就是说当传递的是引用数据类型时，对形参的改变仍会影响实参的值，这是因为此时“值”传递中的值时内存地址值，对形参的修改实际上修改了地址指向的内存中的值，从而影响到了指向同样地址的实参
        - 但当我们为形参new一个新对象时，原本的实参就不会收到影响，因为此时只是更改了拷贝的引用，而并没有改变原始的引用，原始的引用仍然指向原来的对象。
        - 如果不给实例化后的类赋变量名就成为匿名对象，他是一次性的（只能被调用一次）（常被当作实参传入给形参）

# 5. 面向对象特征一：封装性
## 5.1 封装的需要
- 高内聚：类的内部数据操作细节自己完成，不允许外部干涉；
- 低耦合：仅暴露少量的方法给外部使用，尽量方便外部调用。
- 封装性就要求我们把类的属性和方法详细只对特定的类和对象开放，只把需要的接口暴露出来
### 5.2 封装的实现
- Java中的封装主要依靠权限修饰符实现：
`public,protected,缺省,private`

| 修饰符 | 本类内部 | 包内 | 包外子类 | 包外非子类 |
| --- | --- | --- | --- | --- |
| public | &check; | &check; | &check; | &check; |
| protected | &check; | &check; | &check; | &cross; |
| 缺省 | &check; | &check; | &cross; | &cross; |
| private | &check; | &cross; | &cross; | &cross; |

- 对类只能使用前两种修饰符修饰:public和缺省
- 类内部的对象（对象与方法）可以用四种修饰符修饰

## 5.3 封装性的体现
- 私有化：在使用时将属性定义为`private`，从而无法在外部对属性直接进行修改，需要使用对象封装好的方法(`get,set`方法)对属性进行修改。从而可以在该方法里面加入控制逻辑，限制对成员变量的不合理访问。还可以进行数据检查，从而有利于保证对象信息的完整性
- 类中不需要暴露的方法，例如排序方法中的`swap()`
- 单例模式中构造器的private，避免在类外创造实例


# 6 类的成员之三：构造器（构造方法）（Constructor）
## 6.1 构造器的作用
- new对象，并在new对象的时候为实例变量赋值
- 类似python中的`__init__`(实际实例化的是`__new__`)方法，两者都承担创建和初始化对象的任务
- 例如`Person p = new Person(“Peter”,15) `

## 6.2 构造器的语法格式

```
[修饰符] class 类名{
    [修饰符] 构造器名(){
        // 实例初始化代码
    }
    
    [修饰符] 构造器名(参数列表){
        // 实例初始化代码
    }
}

```
- 构造器名必须与所在类的类名保持一直
- 由于承担了初始化的任务，因此构造器没有返回值(void也不需要)
- 构造器的修饰符只能是权限修饰符如`private和public`，不能是其他修饰符例如`static，final，synchronized、abstract、native`等等

- Q1:为什么之前没有特意设置构造器，我们仍能通过new方法实例化对象？
    - 因为当类中没有声明显示构造器时，系统会默认提供一个无参的构造器并且该构造器的修饰符默认与类的修饰符相同
    - 而当显示的声明构造器之后，系统就不再提供默认的空参构造器了
    - 我们可以声明多个构造器，构造器之间可以重载

- Q2:联想Python中的`__init__`方法，java构造器中有没有类似的`self`关键字呢？
    - 有的，Java中的称为`this`关键字，当我们自己声明构造器时，用或不用都可以编译通过。但使用`this`关键字有如下一些好处，能使我们的代码更易读：
1. 使用`this`关键字可以避免构造器参数和类属性之间重名的冲突：
        
```
public class MyClass {
    private int value;

    public MyClass(int value) {
        this.value = value;
    }
}
```

2.使用`this`关键字方便使用构造器之间的调用，同时也可以用构造器之间的调用为属性赋默认值，可参考下面的代码：

```
public class MyClass {
    private int value1;
    private int value2;

    public MyClass(int value1) {
       this(value1, 0);
    }
    
    public MyClass(int value1, int value2) {
       this.value1 = value1;
       this.value2 = value2;
    }
}
```
- 担当我们使用this实现构造器之间调用的时候需要注意
    - 不要出现递归调用，注意不要出现回环（n个构造器n个this(参数列表)）
    - 在类的一个构造器中，最多只能声明一个"this(参数列表)，且this()和this(实参列表)只能声明在构造器首行
- this也不仅仅是在构造器中使用，在方法中同样可以用来使用，例如返回当前对象的类似set方法中，区分属性与参数的用法等都有用到
- 另外，使用this访问属性和方法时，如果在本类中未找到，会从父类中查找,这个在继承中会讲到。

# 8.面向对象特征二：继承性

## 8.1 继承的需要
- 自上而下的继承：Person - Student
- 自下而上的抽象：对不同类中相同的属性方法进行抽取：Rabbit，Dog - Animal
- 减少代码冗余，提高复用性，实现内容的扩展

## 8.2 继承的语法
- 继承依赖extends关键字，格式如下：

```
[修饰符] class A {
    
}

[修饰符] class B extends B {
    
}
```
- 其中A称为父类，超类(SuperClass)或者基类(base class)
- B称为子类(sub class)，派生类(derived class)

## 8.3 继承的细节

1. 子类会继承父类所有的实例变量和实例方法
- 当子类对象被创建时，在堆中给对象申请内存时，就要看子类和父类都声明了什么实例变量，这些实例变量都要分配内存。
- 当子类对象调用方法时，编译器会先在子类模板中看该类是否有这个方法，如果没找到，会看它的父类甚至父类的父类是否声明了这个方法，遵循**从下往上**找的顺序，找到了就停止，一直到根父类都没有找到，就会报编译错误。
2. 继承性与封装性并不冲突-并不能在子类对象中直接访问父类中的private的成员变量与方法
3. Java中声明的类，如果没有显示的声明其父类的话，则其默认继承于java.lang.Object
3. Java支持多次继承。
```
class A{}
class B extends A{}
class C extends B{}
```

## 8.4 方法重写

### 8.4.1 重写的需要

- 有时子类并不需要父类中声明的全部的方法，**那么就需要对从父类中继承来的方法进行改造（区别于重载Overload对参数列表的修改，这里的改造指对方法体的改写），称为方法的重写(override,overwrite)**，也被称为方法的重置与覆盖，而在执行时，子类的方法也将覆盖父类的方法。

### 8.4.2 重写的语法
- 一般在需要重写的方法上加 `@Override`（便于让ide帮助我们检查格式并提高可读性，但写不写并不会影响重写的覆盖 ）


```
@Override
[权限修饰符][返回值]方法名(参数列表){
    方法体
}
```
- 子类中重写的方法必须与父类中被重写的方法的**方法名**与**参数列表**保持一致
- 子类重写的方法的权限修饰符应该不小于父类被重写方法的权限修饰符
    - 子类中不能重写父类中为private的方法（会被认为是新定义的方法）
- 关于返回值，子类重写的方法的返回值类型不能大于父类被重写的方法的返回值类型。：
    - 父类void->子类必须是void；
    - 父类基本数据类型->子类的返回值类型必须和父类中被重写方法返回值类型相同
    - 父类是引用数据类型（比如类）->子类的返回值类型必须与父类中被重写方法返回值类型相同或是该返回值类型的子类
- 子类方法抛出的异常不能大于父类被重写方法的异常 

## 8.5 super关键字

### 8.5.1 对于super的理解
- 对比`this`关键字，`super`用于访问父类中的属性、成员方法以及在子类构造器中调用父类的构造器（以不影响封装性为前提）



### 8.5.2 为什么需要super关键字/使用super关键字的场景

- 例子1：在子类重写父类的方法后，我想调用父类中被重写的方法
- 例子2：我在子类中定义了与父类中属性同名的属性，应该怎么做区分
- 与this一样，在直接引用父类属性和方法时，"`super.`"其实都被省略了
- 但当遇到上面两个场景时，我们必须用`super`表示调用父类被重写的方法/属性

### 8.5.3 当方法/属性被调用时，是怎样寻找匹配的？
- 方法/属性前面没有`super.和this.`：先从子类找匹配方法，如果没有，再从直接父类找，再没有，继续往上追溯
- 方法/属性前面有`this.`：先从子类找匹配方法，如果没有，再从直接父类找，再没有，继续往上追溯
- 方法/属性前面有`super.`：从当前子类的直接父类找，如果没有，继续往上追溯
- 因此没有重构的方法，`this.`和`super.`都是一样的，或者也可以直接省略

### 8.5.4 super调用构造器
- 子类继承父类时，不会继承父类的构造器，只能通过“`super(形参列表)`”的方式调用父类指定的构造器。
- 规定：“`super(形参列表)`”，必须声明在构造器的首行。
- 我们前面讲过，在构造器的首行可以使用"`this(形参列表)`"，调用本类中重载的构造器， 结合上一条，结论：在构造器的首行，"`this(形参列表)`" 和"`super(形参列表)`"只能二选一。
- 如果在子类构造器的首行既没有显示调用"`this(形参列表)`"，也没有显式调用"`super(形参列表)`"，则子类此构造器默认调用（省略）"`super()`"，即调用父类中空参的构造器。
- 同样注意避免回环

## 8.6 子类对象创建时的顺序

- 创建子类对象时一定会调用父类的构造器
- 且创建时本质上是先创造了父类对象，并沿着构造器一级一级向下构造

- Q；那先后调用了父类和子类的构造器，是否会创造多个对象，然后只把子类对象暴露出来呢？
    - 错误的，这是一个常见的误解，当我们创建一个子类的对象时，只会创建一个对象，然后按照继承层级，从上到下（从Object开始，最后到子类）初始化这个对象。整个过程中不会创建出多个对象来，只是分步对同一个对象进行初始化。
    - 这也是为什么我们在创建一个子类对象时，可以使用一个父类引用（superclass reference）来指向它。这个父类引用并不是指向另一个父类对象，它其实就是指向那个子类对象，只不过被“视作”是父类对象来操作罢了。


## 9.多态性

### 9.1 对多态的理解
- 多态性的定义：是面向对象中最重要的概念，在Java中的体现：对象的多态性：父类的引用指向子类的对象：`格式：（父类类型：指子类继承的父类类型，或者实现的接口类型）`
- 我对于多态的理解：从字面理解，多态就是多种形态，当不同的对象去完成时会产生出不同的状态。而在Java中可以理解为在方法的编写时将父类作为形参，将子类作为实参传入从而达到方法的灵活使用(在使用时根据具体使用的子类调用其重写的方法)。
- 因此多态也有三个前置条件：**继承**+（子类）**重写**（父类方法）+**父类引用指向子类对象**（多态的语法格式）

### 9.2 多态的使用
- 多态也被称为虚拟方法调用，简称虚方法
- Java引用变量有两个类型：**编译时类型**和**运行时类型**。编译时类型由**声明该变量时使用的类型**（在多态中可以理解为父类充当的形参，方法也就是**被**重写的方法）决定，运行时类型由实际赋给该变量的对象决定（多态中理解为子类充当的实参，方法也就是重写的方法）。简称：编译时，看左边；运行时，看右边。
- 多态的利弊：
    - 好处：多态的特性允许我们定义一种统一的接口，来表示一般类别的行为，然后通过继承和重写，让不同的子类以不同的方式来实现这些行为，减少代码的冗余。
    

    - 弊端：一个引用类型变量如果声明为父类的类型，但实际引用的是子类对象，那么该变量就**不能**再访问子类中添加的**属性和方法**。
    
```

    public void VehicleLanuch(Vehicle vehicle) {
        vehicle.run();
    }

    public static void main(String[] args) {
        VehicleTest vt = new VehicleTest();

        vt.VehicleLanuch(yiqi);
        //System.out.println(yiqi.volume);//父类引用指向的子类对象无法再访问子类中的属性，因此编译错误无法通过

### 9.3 向上转型与向下转型

#### 9.3.1 为什么要转型
- 因为多态，就一定会有把子类对象赋值给父类变量的时候，这个时候，在编译期间，就会出现类型转换的现象。但是，使用父类变量接收了子类对象之后，我们就不能调用子类拥有，而父类没有的方法了。这也是多态给我们带来的一点"小麻烦"。所以，想要调用子类特有的方法，必须做类型转换，使得编译通过。
![image](https://github.com/luobin7/-java-/raw/main/%E7%AC%AC07%E7%AB%A0_%E9%9D%A2%E5%90%91%E5%AF%B9%E8%B1%A1%E7%BC%96%E7%A8%8B%EF%BC%88%E8%BF%9B%E9%98%B6%EF%BC%89/images/image-20220324235337563.png)

#### 9.3.2 什么叫转型
- 向上转型是将子类（右边对象/变量的类型）提升为父类（左边的变量的类型）
    - 此时，编译时按照左边变量的类型处理，就只能调用父类中有的变量和方法，不能调用子类特有的变量和方法了
    - 但是，运行时，仍然是对象本身的类型，所以执行的方法是子类重写的方法体。
    - 此时，一定是安全的，而且也是自动完成的
    - `Aniaml animal = New Dog(); Dog d = (Dog)animal`多态就是一种向上转型

- 向下转型：将父类的类型降低为其子类类型。

    - 此时，编译时按照左边变量的类型处理，就可以调用子类特有的变量和方法了
    - 但是，运行时，仍然是对象本身的类型
    - 不是所有通过编译的向下转型都是正确的，可能会发生ClassCastException，为了安全，可以通过instanceof关键字进行判断
    - `Cat cat = (Cat) animal`编译错误，dog与cat之间并不存在子父类关系
    



#### 9.3.3 instanceof关键字
- Java提供了 instanceof 关键字，给引用变量做类型的校验：

```

对象a instanceof 数据类型A 
```
```

    cat.hunt()
}

## 11.Static关键字

- 回顾类中的实例变量（非static的成员变量），它属于类的每一个实例对象，例如Circle类中的radius属性，c1中radius变化并不会影响c2中radius的取值。
- 而static关键字修饰的变量就能被类的所有实例对象所共享，被称为类属性，就像类Chinese中的nationality属性，类方法也同理。

### 11.1 类属性


1. **语法格式**
```
[修饰符] class 类{
	[其他修饰符] static 数据类型 变量名;
}
```


2. **适用范围**：在Java类中，可用static修饰属性、方法、代码块、内部类
- 被修饰后的成员具备以下特点：
    - 随着类的加载而加载，在jdk6及之前存放在方法区中，在jdk8及以后存在堆中
    - 优先于对象存在，随着类的加载而加载（只有一份），随着类的消亡而消亡
    - 修饰的成员，被所有对象所共享
    - 访问权限允许时，可不创建对象，直接被类调用

### 11.2 类方法

1. **语法格式**
```
[修饰符] class 类{
	[其他修饰符] static 返回值类型 方法名(形参列表){
        方法体
    }
}
```

2. **静态方法特点**
- static方法内部只能方法类的static修饰的方法或者属性，不能访问非static的结构。
- 静态方法可以被子类继承，但不能被子类重写。
- 静态方法的调用都只看编译时类型。
- 因为不需要实例就可以访问static方法，因此static方法内部不能有this，也不能有super。如果有重名问题，使用“类名.”进行区别。


### 11.3 什么时候需要使用类属性和类方法
- 类属性：共享的属性，例如Math类中的PI,（练习中还用类属性实现了实例化对象个数的统计-在构造器中加入一个自增的类属性）
- 类方法：该方法的结果只依赖于输入的参数（不依赖于类内的实例属性），还有一些工具类的方法，例如Array类中的各种排序方法，Math类中的sqrt()和random()

### 12.2 单例模式

#### 12.2.1 什么叫单例模式
- 一个类只能有一个对象

#### 12.2.2 实现思路

- 将类的构造器私有化，只能调用该类的某个静态方法以返回类内部创建的对象，静态方法只能访问类中的静态成员变量，所以，指向类内部产生的该类对象的变量也必须定义成静态的。

#### 12.2.3 两种实现方式
- 饿汉式
- 类随着类的加载在内存中直接初始化，线程安全
- 在内存中占用时间较长，类似内存泄漏

```
class Singleton {
    // 1.私有化构造器
    private Singleton() {
    }

    // 2.内部提供一个当前类的实例
    // 4.此实例也必须静态化
    private static Singleton single = new Singleton();

    // 3.提供公共的静态的方法，返回当前类的对象
    public static Singleton getInstance() {
        return single;
    }
}

```




- 懒汉式
- 使用gettter方法后加载，发挥延迟加载的优势

```
class Singleton {
    // 1.私有化构造器
    private Singleton() {
    }
    // 2.内部提供一个当前类的实例
    // 4.此实例也必须静态化
    private static Singleton single;
    // 3.提供公共的静态的方法，返回当前类的对象
    public static Singleton getInstance() {
        if(single == null) {
            single = new Singleton();
        }
        return single;
    }
}

```

- 静态代码块随着类的加载而执行，进而也只会执行一次，可用来初始化类的信息
- 而非静态代码块随着对象的创建而执行，进而每创建一个新对象都会执行一次，且早于构造器执行，可用于初始化对象的信息
- 有多个（静态/非静态）代码块则按照顺序执行

### 13.3.类中属性赋值的顺序

- 默认初始化-显式初始化/代码块-构造器初始化-利用公开的方法/属性修改

## 14.final关键字

- 表示不可继承/重写，"终章"
- final修饰的类比如String,StringBuffer,StringBuilder三个字符串的类就不能继承
- final修饰的方法则不可被子类重写，例如Object中的getClass()方法用final修饰，就不能重写了
- final修饰变量，则该变量就不能被修改了，即成为了"常量"，此时的变量建议使用全大写
- 区分于static，final修饰的成员变量是跟着对象走的，因此我们只能在三个地方赋final值：显性赋值，代码块赋值，构造器赋值；而static关键字是跟着类走的
- 而final和static一起修饰变量，该变量就成为了全局常量，使用修饰PI这种变量。
- 为什么final不能修饰构造器：构造器不可继承，本身就是不可重写的

## 15.抽象方法和抽象类
- 只有方法签名，没有方法体的方法称为抽象方法，而包含抽象方法的类称为抽象类
- "抽象"类不能实例化，而抽象方法
- 例如 几何图形-圆形/矩形，而在几何图形这个抽象类中，就包含求周长和求面积的抽象方法

### 15.1 语法格式
- 抽象类：被abstract修饰的类。
- 抽象方法：被abstract修饰没有方法体的方法。
- 抽象类：

```
[权限修饰符] abstract class 类名{
    
}
[权限修饰符] abstract class 类名 extends 父类{
    
}
```
- 抽象方法（注意抽象方法是没有方法体的）：

```
[其他修饰符] abstract 返回值类型 方法名([形参列表]);
```

- 抽象类的子类只有把所有的抽象方法都重写才不算抽象类

### 15.2 应用举例：模板方法设计模式

```
abstract class Template {
    public final void getTime() {
        long start = System.currentTimeMillis();
        code();
        long end = System.currentTimeMillis();
        System.out.println("执行时间是：" + (end - start));
    }

    public abstract void code();
}

class SubTemplate extends Template {
    public void code() {
        for (int i = 0; i < 10000; i++) {
            System.out.println(i);
        }
    }
// 计算程序运行时间
}

```


```
package com.atguigu.java;
//抽象类的应用：模板方法的设计模式
public class TemplateMethodTest {

	public static void main(String[] args) {
		BankTemplateMethod btm = new DrawMoney();
		btm.process();

		BankTemplateMethod btm2 = new ManageMoney();
		btm2.process();
	}
}
abstract class BankTemplateMethod {
	// 具体方法
	public void takeNumber() {
		System.out.println("取号排队");
	}

	public abstract void transact(); // 办理具体的业务 //钩子方法

	public void evaluate() {
		System.out.println("反馈评分");
	}

	// 模板方法，把基本操作组合到一起，子类一般不能重写
	public final void process() {
		this.takeNumber();

		this.transact();// 像个钩子，具体执行时，挂哪个子类，就执行哪个子类的实现代码

		this.evaluate();
	}
}

class DrawMoney extends BankTemplateMethod {
	public void transact() {
		System.out.println("我要取款！！！");
	}
}

class ManageMoney extends BankTemplateMethod {
	public void transact() {
		System.out.println("我要理财！我这里有2000万美元!!");
	}
}

## 16.interface关键字：接口
- 接口是和类平级的概念
- 为模块只见提供一种低耦合的连接方式
- 本质是一种规范，也可以理解为一种去除了构造器与属性，更加纯粹的抽象类（从对身份的继承到对能力的拓展）

### 16.1 定义格式
- 接口使用interface关键字，也会被编译为.class文件。但要注意他并不是类文件，而是一种引用数据类型。
> 引用数据类型：数组，类，枚举，接口，注解
- 具体的声明格式：
- 
```
[修饰符] interface 接口名{
    //接口的成员列表：
    // 公共的静态常量
    // 公共的抽象方法
    
    // 公共的默认方法（JDK1.8以上）
    // 公共的静态方法（JDK1.8以上）
    // 私有方法（JDK1.9以上）
}
```

```
public interface USB3{
    // 静态常量
    long MAX_SPEED = 500*1024*1024
    
    //抽象方法
    void in()
    
    void out()
    
    //默认方法
    default void start(){
        System.out.println("开始");
    }
    default void stop(){
        System.out.println("结束");
    }

    //静态方法
    static void show(){
        System.out.println("USB 3.0可以同步全速地进行读写操作");
    }
}
```
- 在这些成员中：
    - 静态常量前的public static final被省略了
    - 公共抽象方法前的public abstract被省略了
    - 而公共默认/静态方法前的public在这里都被省略了，建议保留，且后面的default/static不能省略
    - 在jdk9.0中，接口又增加了私有方法
    - 除此之外，接口中是没有构造器的

### 16.3 类对接口的实现

- 接口让类突破了唯一继承的局限性，可以通过实现多个接口来实现公共的方法
- 格式：
- 
```
[修饰符] class 类名 implements interface A,interface B,interface C .....{
    
}

[修饰符] class 实现类 extends 父类 implements interface 1，interface2，interface3。。。{
    // 重写接口中所有抽象方法【必须】，当然如果实现类是抽象类，那么可以不重写
  	// 重写接口中默认方法【可选】
}
```

- 与抽象类的要求一样，如果实现接口的类非抽象类，则他必须全部重写接口中所有的抽象方法

- 接口之间可以多继承
```

### 16.5 接口的多态性
- 使用接口指向实现接口的对象
- 接口可以通过将其内部的抽象方法重写而创造一个匿名类：他的本质其实是创造一个匿名类并用这个类实现接口
- instanceof还能用来检查类是否有对接口的实现，后续可以通过强转转到接口类型调用方法。

### 16.6 接口的演变
- 在jdk8之前，接口中只能定义抽象方法
- jdk8中，接口引入了静态方法与默认方法（静态只能被接口本身调用而不能被其实现类调用,而默认方法可以被其实现类继承）
- 接口冲突：继承了多个类中有重名同参数的默认方法
- 如果子类继承的父类和它实现的接口中有同名同参数的方法，优先调用的会是父类中的方法（类>接口）（前提你没有在子类中重写该方法）
- 承接上条，如果此时我想调用接口中的方法，那么就用`接口名.super.方法名`，此时super不仅表示继承，也表示实现的关系。(这种方式仅限于解决接口默认方法之间的冲突)

```
class ParentClass {
    public void someMethod() {
        System.out.println("ParentClass's version of someMethod");
    }
}

interface InterfaceWithDefault {
    default void someMethod() {
        System.out.println("InterfaceWithDefault's version of someMethod");
    }
}

class ChildClass extends ParentClass implements InterfaceWithDefault {
    // 子类覆盖方法
    public void someMethod() {
        InterfaceWithDefault.super.someMethod(); // 显式调用接口中的默认方法
        // 如果是静态方法就可以InterfaceWithDefault.someMethod()
    }
}

public class Test {
    public static void main(String[] args) {
        ChildClass instance = new ChildClass();
        instance.someMethod();
    }
}
```
- 在jdk9中，接口中还引入了不对外暴露的私有方法，主要用于默认方法方法体的构建中

## 17 内部类（InnerClass）

### 17.1 什么叫内部类？什么情况使用内部类？
- A在B内，A为InnerClass，B为OuterClass
- A的内部需要一个较为完整的B结构参与描述，且B只服务于A
- 高内聚，低耦合
- 举例：Thread类中的State类，表示线程的生命周期-+-----------------,HashMap类中的Node类，封装内部的Key-Value

- 局部内部类：在类的成员内部的类（构造器，代码块，方法）

## 18 枚举类
- 若针对某个类，其对象是固定个数的，则建议将其设置为枚举类
- 若其对象只有一个，便可以将其看作单例模式

### 18.1 枚举类的定义
- 在JDK5.0之前，我们要手动实现枚举（将类对象设置为静态对象）
- 在JDK5.0后，Java引入了enum关键字

```
【修饰符】 enum 枚举类名{
    常量对象列表
}

【修饰符】 enum 枚举类名{
    常量对象列表;
    
    对象的实例变量列表;
}
```
- 使用enum关键字的枚举类，其父类都是java.lang.Enum，不要显示的定义其父类，否则会报错吗
- 注意：枚举类的构造器都是private访问级别的，与一般类中构造器的public级别作出区分。这个private也可以省略，Java会自动补充该前缀。

### 18.2 Enum类中常用的方法

```
String toString(): 默认返回的是常量名（对象名），可以继续手动重写该方法！
    
static 枚举类型[] values():返回枚举类型的对象数组。该方法可以很方便地遍历所有的枚举值，是一个静态方法
    
static 枚举类型 valueOf(String name)：可以把一个字符串转为对应的枚举类对象。要求字符串必须是枚举类对象的“名字”。如不是，会有运行时异常：IllegalArgumentException。（其实就是返回String对应的enum对象）
    
String name():得到当前枚举常量的名称。建议优先使用toString()。
    
int ordinal():返回当前枚举常量的次序号，默认从0开始

```
### 19.2 在枚举类中实现接口
- 不同枚举类对象调用接口调用的是同一个方法
- 不同枚举类对象调用接口调用的是不同的方法：依靠内部匿名类实现

```

}

//2、如果枚举类的常量可以继续重写抽象方法!

    常量名1(参数){
        //抽象接口方法的实现或重写
    },
    常量名2(参数){
        //抽象方法的实现或重写
    },
    //...

## 20. Annotation 注解

### 20.1 注解是什么
- 注解在jdk5.0中被引入：`@注解名`
- 不同于注释，注解是会被编译器编译，影响代码的功能的
- 现阶段常见的三种注解：
    - `@Override`:限定重写父类方法时使用，只能用于方法
    - `@deprecated`:已过时，不建议使用
    - `@suppresswarnings`
- 在后面的框架中常替代配置文件


### 20.2 元注解
- JDK1.5在java.lang.annotation包定义了4个标准的meta-annotation类型，它们被用来提供对其它 annotation类型作说明。
    - **@Target：**用于描述注解的使用范围，可以通过枚举类型ElementType的10个常量对象来指定`TYPE，METHOD，CONSTRUCTOR，PACKAGE.....`
    - **@Retention：**用于描述注解的生命周期可以通过枚举类型RetentionPolicy的3个常量对象来指定SOURCE（源代码）、CLASS（字节码）、RUNTIME（运行时）唯有RUNTIME阶段才能被反射读取到。
    - @Documented：表明这个注解应该被 javadoc工具记录。
    - **@Inherited：**允许子类继承父类中的注解
    - 自定义注解
    
```
